# 4. Рейтинги

Самая важная и самая запутанная часть системы. Здесь описано, как работает код сейчас. История
решений («почему так») — в `db/rating-semantics.md`, а комментарии в миграциях `013`, `021`,
`025`, `031`, `035`, `038` объясняют каждое изменение.

## Две формы хранения

| | Что | Где | Кто читает |
|---|---|---|---|
| **Вьюхи** | расчёт баллов и мест «на лету» из `student_results` | `v_*_year_scores` → `v_*_places` (год), `v_*_month_scores` → `v_*_month_places` (месяц) | пересчёт (годовые), страницы рейтингов в месячном срезе (месячные) |
| **Таблицы `*_year_ratings`** | материализованные баллы и места за учебный год | `student_year_ratings`, `teacher_year_ratings`, `school_year_ratings`, `district_year_ratings`, `region_year_ratings` | годовые рейтинги `/stats`, профили, карточки, списки, архив |

Ключ каждой таблицы — `(сущность, year, exam_type_id)`. `year` — год начала учебного года.

Важное следствие: **годовые цифры на экранах — это то, что записал последний пересчёт**, а не
живой расчёт. Загруженные результаты появятся в годовых рейтингах только после пересчёта.
Месячные срезы на `/stats` считаются вьюхами при каждом запросе.

## Пересчёт

`StatsServicePg.updateAllStats(year?)` в `src/services/stats.service.pg.ts`. Пересчитывает
текущий учебный год, или переданный год перед его закрытием.

Кто запускает:

- кнопка **«Reytinqləri yenilə»** на `/stats` (только admin/superadmin) → `POST /api/stats/all`.
  **После каждой загрузки результатов администратор должен нажать её сам**: импорт рейтинги не
  пересчитывает;
- фоном, без ожидания: после soft delete, восстановления из «Silinənlər» и перевода учителя
  (`refreshRatingsInBackground`);
- финальный пересчёт перед закрытием учебного года (вручную и автоматически).

Есть ещё `POST /api/stats` (`updateStats`, только текущий календарный месяц), но кнопка для неё
во фронтенде закомментирована.

Что делает `updateAllStats`, **одной транзакцией** под `pg_advisory_xact_lock`. Два пересчёта
одновременно не идут, а упавший пересчёт не оставляет стёртых рейтингов:

0. Сверяет `student_results.month/year` с датой экзамена (по дню в Баку). Закрытые годы не трогает.
1. Обнуляет `development_score`, обе награды месяца и `status` у всех результатов года.
2. По каждому месяцу сентябрь–июнь заново раздаёт «Ayın şagirdi» (район и республика) и
   «İnkişaf edən şagird» (правила — в [01-overview.md](01-overview.md#из-чего-складывается-балл-xal)).
3. По каждому типу экзамена с результатами в этом году: `DELETE` + `INSERT ... SELECT` из вьюх в
   пять таблиц по порядку ученик → учитель → школа → район → регион. Регион последним, потому что
   он суммирует районы.

Закрытый год пересчитать нельзя: `assertYearNotClosed` отвечает ошибкой.

## Формулы по уровням

Баллы одного результата (`v_result_points.points`) — сумма четырёх слагаемых:
`participation_score + development_score + student_of_the_month_score +
republic_wide_student_of_the_month_score`.

| Уровень | Балл (`score`) | Средний балл (`average_score`) | Места |
|---|---|---|---|
| Ученик | Σ баллов его результатов за год | `score / число результатов` | `place` — в своём классе по республике; `district_place` — в классе и текущем районе ученика. Фильтра `score > 0` нет |
| Учитель | Σ баллов результатов, у которых **в снимке** этот учитель | `score / teachers.student_count` (хранимое поле, не живой подсчёт) | `place`, `district_place` (район учителя) по `score`; `average_place`, `average_district_place` по среднему. Только `score > 0` |
| Школа | Σ баллов результатов со снимком этой школы | `score / schools.student_count` (у всех школ 1000, намеренно, см. [08-traps.md](08-traps.md)) | как у учителя |
| Район | Σ баллов результатов со снимком этого района | `score / живое число учеников района` | `place`, `average_place`. Только `score > 0` |
| Регион | Σ баллов его районов (по текущей связи район → регион) | `score / живое число учеников региона` | `place`. Только `score > 0` |

Общие правила:

- **Место — `dense_rank()` по сырому `score`** на всех уровнях (`013_ratings_by_raw_score.sql`).
  Раньше было решение ранжировать по среднему, его отменили как неверное понимание заказчика.
  `average_score` показывается как значение («Orta xal»). С `035` рядом хранится второе место по
  среднему (`average_place`, `average_district_place`).
- Сущность с нулевым баллом получает `place = NULL`, а не место в хвосте. У учеников это правило
  не действует.
- Класс ученика в году — один на `(ученик, год, тип)`, берётся из самого позднего результата
  (`031`). Если пересоздать `v_student_year_scores` с `grade` в `GROUP BY`, одна опечатка класса в
  файле даёт две строки на ученика, `INSERT` падает на первичном ключе, и пересчёт не проходит
  ни у кого. Это уже случалось дважды (`009`, затем регресс в `025` и повтор в `031`).
- Разные типы экзаменов не смешиваются: все вьюхи партиционированы по `exam_type_id`. Страница
  `/stats` показывает базовый тип, `/type-ratings` — то же с выбором типа.

## Снимок «где сдавал» (миграция 038)

В `student_results` есть `teacher_id`, `school_id`, `district_id` — учитель, школа и район ученика
**на момент записи результата**. Цепочка снимка: ученик → его учитель → школа учителя → район
школы (а не `students.school_id`). Снимок ставит триггер `student_results_snapshot` на `INSERT`
(и на смену `student_id`). Перезаливка того же экзамена (`ON CONFLICT ... DO UPDATE`) снимок не
меняет.

Зачем: баллы остаются там, где их заработали. Перевод учителя в другую школу или ученика к
другому учителю не уносит прошлые баллы. Новые результаты идут по новым связям. Строки,
записанные до `038`, забэкфилены по связям на 23.10.2026. Для закрытых лет лучшего источника нет.

Результат засчитывается на уровне X, если живы ученик и все сущности снимка от учителя до X
(soft delete, `037`).

По снимку работают также номинация «Ayın şagirdi» по району и фильтры по району, школе и учителю в
месячных списках и на `/exam-results`.

## Место «Filtr üzrə yer»

В таблицах рейтингов есть колонка места внутри текущей выборки (после фильтров по району, школе и
т. д.). Она считается на лету по той метрике, по которой отсортирована таблица: сортировка по
среднему → по `average_score`, любая другая → по `score` (`src/utils/rank-metric.util.ts`). Какая
метрика использована, бэкенд сообщает полем `filterPlaceBasis`. В месячном срезе среднего нет, там
всегда `score`.

## Какой год показывать

Учебный год меняется 1 сентября, а экзамены нового года начинаются позже. Чтобы главные страницы
и профили не опустели, год рейтингов для «неявных» экранов (карточки, профили, реестры) задаёт
тумблер администратора **«Yeni tədris ili»**: `app_settings`, ключ
`ratings.activated_academic_year`, `PUT /api/academic-year/rating-year`. Пока новый год не
активирован, такие экраны показывают прошлый. Логика — `src/services/ratingYear.service.pg.ts`
(`resolveRatingYear`, кэш 60 секунд, сбрасывается при переключении). Страница `/stats` с явно
выбранным годом тумблер не учитывает.

## Месячный срез

`v_*_month_scores` / `v_*_month_places` (`021`, `022`, `025`, `038`) группируют по календарной паре
`(year, month)`. Среднего балла в месячном срезе нет ни на одном уровне: делители годовых средних
для месяца заведомо неверны. Места считаются как в годовых вьюхах. Ничего не материализуется.

## `/statistics` — это не рейтинг

Страница «Statistika» (`statistics.service.pg.ts`) описывает **текущий контингент**: сколько
учеников сейчас учится в школе, распределение по pillə и т. п. Она сознательно идёт по **текущим**
связям, а не по снимку. Числитель по снимку дал бы больше 100 % у школы, куда перевели учителя без
учеников. Рейтинги отвечают на вопрос «кто где набрал», статистика — «кто где учится сейчас».

## Архив прошлых лет

Строки `*_year_ratings` закрытых лет не пересчитываются никогда. Как год закрывается и почему это
важно — в [05-academic-year.md](05-academic-year.md).

Особенности архива, о которых стоит знать:

- 2024/2025 и 2025/2026 посчитаны по правилам своего времени. Pillə тогда брались из файла
  заказчика по числу правильных ответов, а не по процентам. Пересчёт по нынешней шкале исказил бы
  места и уже выданные сертификаты.
- Архив 2025/2026 внутри слегка неоднороден: таблицы учеников, школ и районов писались в разные
  моменты (повышение классов без закрытия года, позже досчёт). Пломба перезаписана миграцией `032`.
  Оставлено как есть.
- `district_year_ratings.average_score` всех лет пересчитан миграцией `035` по живому числу
  учеников района (старый делитель «ученики × школы» был ошибкой из Mongo-эпохи). `score` и места
  не менялись, поэтому пломбы закрытых лет остались валидными.
- Два «дубля» одного человека (ученик перешёл с новым кодом) в архиве не склеиваются. На
  рейтинги учителей, школ и районов это не влияет, бьёт только по личному рейтингу ученика.
