# 8. Ловушки и намеренные решения

Здесь собрано то, что при первом взгляде выглядит как баг, но сделано сознательно, и то, обо что
разработчики уже спотыкались. Прежде чем «чинить» что-то из списка, уточните у владельца.

## Данные, которые выглядят неправильно, но так задумано

| Что видно | Почему так | Что делать |
|---|---|---|
| У **всех школ `student_count = 1000`** | Проставлено вручную по просьбе заказчика. Средний балл школы = `score / 1000`, на места не влияет (места по `score`) | Не пересчитывать из живого числа учеников без явного решения владельца. Из экспорта каталога `studentCount` исключён намеренно |
| `teachers.student_count` не совпадает с реальным числом учеников | Хранимое поле, вводится вручную или из справочного Excel. Это делитель среднего балла учителя | То же: это решение о методике, а не баг |
| Район **Naxçıvan** — точная копия **Gəncə** (те же баллы и ученики, другое число школ) | Демо-данные владельца для показа системы клиентам | Не чистить, не дедуплицировать. При анализе статистики по районам учитывать, что это демо |
| У старых результатов `level` не совпадает с процентной шкалой (например, при `total_score` 15, 25, 47) | До сентября 2026 pillə брались из файла заказчика по числу правильных ответов. Процентная шкала действует для новых загрузок | Не пересчитывать: от pillə зависят балл участия, «İnkişaf», места и выданные сертификаты |
| «Ayın şagirdi» получают только ученики с pillə Lisey | Подтверждённое заказчиком правило. Теперь это настройка типа экзамена `month_award_min_rank` (у базового 6 = Lisey) | Менять настройкой типа, не кодом |
| Нулевые учителя, школы и районы без места (`place = NULL`), а нулевые ученики с местом | Разные правила уровней, оба сохранены сознательно | — |
| Результаты июля и августа не попадают ни в один учебный год | `academic_year` — generated-колонка, учебный год сентябрь–июнь | — |
| Экзамены в БД на `20:00Z` предыдущего дня | Старый фронтенд сохранял полночь по Баку в UTC | Сравнивать даты по календарному дню в `Asia/Baku` |
| Один и тот же человек — два ученика с разными кодами | Перевод с новым кодом. Слияние учеников не делается (решение владельца) | Рейтинги учителей и школ от этого не страдают, только личный рейтинг ученика |
| Архив 2025/2026 слегка неоднороден по таблицам | Таблицы писались в разные моменты, пломба перезаписана миграцией `032` | Не пересчитывать закрытые годы «для сверки» |
| Девочки без пола (`gender = NULL`) получают мужской фон сертификата | `NULL` = неизвестно, по умолчанию мужской вариант | Проставить пол в карточке ученика |
| Цифры на лендинге не меняются | Захардкожены во фронтенде по решению заказчика | Менять в коде лендинга |
| Раздел «Kitabçalar» не виден никому | Скрыт по просьбе заказчика (`canAccessBooklets = false`) | — |
| Годовых титулов «İlin şagirdi …» нет, хотя колонки `*_of_the_year_score` есть | Титулы отложены заказчиком, колонки — заготовки | Не показывать, пока заказчик не попросит |

## Код

- **MongoDB — мёртвый код.** Файлы `services/*.service.ts` без `.pg`, `src/models/*`,
  `src/_backups_ratings_migration/` на проде не исполняются. Живая логика — в `*.pg.ts`
  ([03-architecture.md](03-architecture.md#mongodb--мёртвый-код-не-запасной-вариант)).
- **Тестов нет.** `npm test` в бэкенде — заглушка, во фронтенде спеки почти пустые. Компиляция ничего
  не гарантирует: проверяйте на локальной копии прода.
- **Сырой SQL не проверяется компилятором.** Рейтинги, сертификаты и статистика написаны через
  `sql\`...\``. При переименовании колонок ищите имя текстом.
- **Годовые рейтинги не обновляются сами.** После загрузки результатов нужен «Reytinqləri yenilə»
  ([04-ratings.md](04-ratings.md#пересчёт)).
- **`v_student_year_scores` и класс ученика.** Вьюха должна давать одну строку на
  `(ученик, год, тип)`. Если вернуть `grade` в `GROUP BY`, пересчёт падает целиком (уже было дважды).
- **Вьюхи `students`, `teachers`, `schools`, `districts`** раскрывают `SELECT *` при создании.
  Новая колонка в `*_all` без пересоздания вьюхи для кода не существует.
- **Шкалы pillə кэшируются при старте.** Правка бэндов прямым SQL требует перезапуска.
- **Код района не каскадируется** на школы, а переезд школы в другой район не меняет её код.
- **Роль `moderator` не модерирует.** Очередь «Təsdiq gözləyən məlumatlar» и «Silinənlər» доступны
  только admin/superadmin, и удалять moderator ничего не может.
- **`admin` не может редактировать экзамен** (`PUT /api/exams/:id` и `canEditExams` — только
  superadmin), хотя создавать и удалять может. Решением это нигде не зафиксировано, уточните у
  владельца, прежде чем менять.
- **`/statistics` — по текущим связям, рейтинги — по снимку.** Цифры этих двух страниц для школы
  после перевода учителя законно расходятся.
- **Новая роль с областью видимости** = правка всех контроллеров со скоупингом и всех ключей
  `rbac.config.ts` во фронтенде. Пропущенный ключ — тихий баг.
- **Порядок маршрутов Express.** Статические пути (`/filter`, `/search`, `/activity-stats`)
  объявляйте до `/:id`.
- **Загрузка файлов:** `authMiddleware` всегда до multer.
- **Большие файлы и память.** Контейнер бэкенда ограничен 200 МБ.

## Миграции и деплой

- Запушенную миграцию **не править**, только новым файлом ([07-deploy-operations.md](07-deploy-operations.md#миграции-при-деплое)).
- Пуш в `main` бэкенда = миграции на проде + деплой. Отдельного стенда нет.
- Файла `003_student_result_status.sql` в репозитории нет, хотя он указан в `KNOWN_APPLIED` в
  `apply-pending.sh` и в README миграций. Он был применён вручную до автоматизации и уже есть в
  `schema.sql`. На работу это не влияет.
- В `db/migrations/README.md` у `025c_drop_exam_code.sql` написано «не применена на прод (гейт)».
  Это устарело: миграции применяются строго по порядку и раннер останавливается на первой ошибке,
  а все последующие (`026`–`038`) на проде применены. Колонки `exams.code` в схеме нет.
- Все бэкапы на том же сервере, `~/uploads` не бэкапится ([07-deploy-operations.md](07-deploy-operations.md#бэкапы)).
- `nginx.conf` на сервере нельзя заменять через `mv`/`scp` (bind-mount по inode).
- Не пушить оба репозитория одновременно.

## Известные проблемы

- Аудит прав доступа при подготовке этой документации (23.10.2026) нашёл несколько эндпоинтов,
  где проверка ограничивается «пользователь авторизован» или её нет вовсе там, где она нужна.
  Детали переданы владельцу отдельно, а не в публичный репозиторий. После исправления этот пункт
  нужно убрать.
- `GET /api/schools|teachers|students/repair` меняют данные по `GET` (только admin).
- `DELETE /api/students/` всегда отвечает 403 — мёртвый маршрут.
- `GET /search` у районов, школ и учителей дублирует `GET /`.
- Во фронтенде `/statistics` закрыт только `authGuard`: ученик откроет страницу по прямой ссылке,
  хотя в меню её нет. Данные при этом режет бэкенд.
- Во фронтенде флаги `showRatingColumnsLink`, `showStatsUpdateButton`, `showBulkActions`,
  `showExportButtons` в `rbac.config.ts` нигде не читаются.
- Шаблон результатов для секции типа (`GET /api/exam-types/:id/results-template.xlsx`) доступен
  любой роли, а для экзамена — только admin.
