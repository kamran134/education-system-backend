# 5. Учебный год: закрытие, повышение классов, архив

## Календарь

| Когда | Что | Кто |
|---|---|---|
| сентябрь–июнь | экзамены, загрузка результатов, «Reytinqləri yenilə» | admin |
| июнь–август | **закрыть** уходящий год (`/admin/academic-year`) | admin |
| июль–август | **повысить классы** (только после закрытия) | admin |
| 1 сентября | `getCurrentAcademicYear()` переключается на новый год; незакрытый старый год закрывается автоматически при следующем старте сервера | система |
| когда пошли экзамены нового года | включить тумблер «Yeni tədris ili» | admin |

Порядок **«закрыть → повысить»** обязателен и проверяется кодом.

## Закрытие года

`POST /api/academic-year/closure` с `{ confirm: true }` (предпросмотр — `GET` того же адреса).
Контроллер `gradePromotion.controller.ts::executeClosure`, сервис
`academicYearClosure.service.pg.ts`.

1. Разрешено только в июне–августе. С сентября «текущим» уже считается новый год, и его закрытие
   заморозило бы пустые рейтинги (409).
2. Финальный `updateAllStats(year)`: год ещё открыт, пересчёт проходит.
3. В одной транзакции:
   - строка в `academic_year_closures`: год, кто закрыл, причина, **контрольные суммы**
     `count(*)` и `sum(score)` по каждой из пяти `*_year_ratings`;
   - `+1` к `teachers.pedagogical_experience_years` у всех, у кого стаж задан.

   Первичный ключ по году защищает от повторного и параллельного закрытия (23505 → 409). Стаж
   тогда тоже не увеличится.

После закрытия любой пересчёт этого года отказывает (`assertYearNotClosed`). Строки
`*_year_ratings` закрытого года больше не меняются. Контрольные суммы позволяют позже доказать,
что архив не испорчен, без старого дампа.

## Автозакрытие

При каждом старте бэкенда (`index.ts` → `ensureFinishedYearsClosed`) закрываются все годы меньше
текущего, у которых есть строки рейтингов и нет записи о закрытии (`closed_reason = 'auto'`,
`closed_by = NULL`). Только для **только что закончившегося** года и только если классы на новый
год ещё не повышены, перед пломбой делается финальный пересчёт. Иначе пломба снимается с таблиц
как есть.

Таймера внутри процесса нет: автозакрытие срабатывает на старте контейнера. На сервере контейнеры
перезапускаются кроном каждое 1-е число месяца в 03:00 (обновление TLS-сертификата, см.
[07-deploy-operations.md](07-deploy-operations.md)), плюс при каждом деплое. Практически год
закрывается утром 1 сентября. Это предохранитель: правильный путь — ручное закрытие летом.

## Повышение классов

`POST /api/academic-year/promotion` с `{ confirm: true }` (предпросмотр — `GET`). Сервис
`gradePromotion.service.pg.ts`.

- Разрешено только в июле–августе.
- 409 «Əvvəlcə … tədris ilini bağlayın», пока уходящий год не закрыт.
- Одна транзакция:
  1. запись в `grade_promotion_logs` (уникальность по учебному году, повторный запуск невозможен);
  2. снимок уходящего года в `student_grade_history`: класс из реестра, поверх него класс из
     результатов, если они есть;
  3. `grade + 1` всем ученикам с `grade < 11`, **включая скрытых** soft delete, чтобы
     восстановленный в следующем году ученик оказался в правильном классе. Ученики 11-го класса
     остаются в 11-м;
  4. снимок нового года в `student_grade_history`.

Зачем такой порядок. Исторически баллы учителей и школ шли по текущим связям учеников, и пересчёт
уходящего года после повышения давал другие цифры. Так случилось в 2026-м: классы повысили
03.08 без закрытия, автозакрытие 01.09 опломбировало недосчитанный архив, пришлось перепломбировать
миграцией `032`. С `031` класс ученика в году берётся из его результатов, а с `038` баллы
учителей, школ и районов идут по снимку в результатах. Поэтому повышение больше не искажает
пересчёт, но проверка оставлена как страховка.

## История классов

`student_grade_history (student_id, academic_year, grade)` (`018`) — в каком классе был ученик в
каждом году. Ею пользуются реестры и архив прошлых лет: без неё после повышения ученик в
прошлогоднем списке выглядел бы уже в новом классе.

## Тумблер «Yeni tədris ili»

`PUT /api/academic-year/rating-year`, хранится в `app_settings` под ключом
`ratings.activated_academic_year`. Пока он не включён, главные страницы, профили и карточки
показывают рейтинги прошлого года. Включать, когда в новом году появились первые результаты и
сделан пересчёт. Подробнее — [04-ratings.md](04-ratings.md#какой-год-показывать).

## Архив в интерфейсе

На странице `/admin/academic-year` во фронтенде собраны все три действия: «Tədris ilini bağla»,
«Sinifləri yüksəlt» (недоступна, пока год не закрыт) и тумблер «Yeni tədris ili». Рейтинги прошлых лет открываются на `/stats` выбором года и
читаются из `*_year_ratings`. Скрытые soft delete сущности из архивных списков просто пропадают,
сами строки архива не меняются.

## Годовые титулы — отложены

Награды «İlin şagirdi / müəllimi / məktəbi / rayonu» как титул (а не вкладка рейтинга) спроектированы
(таблица `year_awards`), но **не реализованы по решению заказчика**: показывать, когда он скажет.
Титул — производная от замороженного архива (`place <= N`), поэтому его можно посчитать за любой
закрытый год задним числом. Колонки `*_of_the_year_score` в таблицах сущностей — мёртвые заготовки,
их убирают вместе с реализацией.
