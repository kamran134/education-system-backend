# 1. Что это за система

**İSİM** — система ежемесячных экзаменов и рейтингов для школ Азербайджана. Ученики раз в месяц
(«aylıq») пишут централизованный экзамен. Результаты загружает администратор из Excel-файла
заказчика. Из результатов система считает баллы и места для пяти уровней: ученик, учитель, школа,
район («Təhsil sektoru») и региональное управление образования («Regional Təhsil İdarəsi», RTİ).
Кроме того, она выдаёт именные сертификаты с QR-проверкой и показывает профили и статистику.

Прод: `https://isim.kpm.az`. Публичная часть — лендинг `/`, страница методики `/metodika` и проверка
сертификата `/sertifikat/:token`. Остальное доступно только после входа.

Код живёт в двух репозиториях:

| Репозиторий | Что внутри |
|---|---|
| `education-system-backend` (этот) | REST API: Express 4 + TypeScript + Kysely, PostgreSQL 17. Миграции БД, деплой |
| `education-system-frontend` | SPA: Angular 21 (standalone-компоненты), Tailwind, собственный UI-кит |

## Иерархия и коды сущностей

```
Region (RTİ) → District (район) → School → Teacher → Student
```

У каждой сущности, кроме региона, есть числовой бизнес-код `code`. **Код потомка арифметически
содержит код родителя** (`src/utils/entity-codes.const.ts`):

| Сущность | Знаков | Как устроен | Пример |
|---|---|---|---|
| District | 3 | свой | `117` |
| School | 5 | `district * 100 + nn` | `11704` |
| Teacher | 7 | `school * 100 + nn` | `1170412` |
| Student | 10 | `teacher * 1000 + nnn` | `1170412037` |
| Region | 2 | своё пространство `10–21`, в иерархию кодов **не входит** | `14` |

Отсюда: `teacher = floor(student / 1000)`, `school = floor(student / 100000)`,
`district = floor(student / 10000000)`.

- Первичный ключ везде — суррогатный `id` (bigserial). `code` — бизнес-ключ, `UNIQUE`, но меняется.
- Смена кода школы или учителя **каскадно** пересчитывает коды всех потомков в той же транзакции и
  пишет каждую замену в `code_change_logs` (`src/utils/code-cascade.util.ts`). Смена кода **района**
  не каскадируется: известный пробел, функции `cascadeDistrictCodeToSchools` нет.
- Коды учеников приходят только из файла заказчика. Сервер их не генерирует.

## Роли

Роль хранится в `users.role`. Пользователь привязан к своей сущности полем `region_id`,
`district_id`, `school_id`, `teacher_id` или `student_id`. Эта привязка попадает в JWT и определяет,
какие данные он видит.

| Роль | Кто это | Видит | Может |
|---|---|---|---|
| `superadmin` | владелец системы | всё | всё, включая правку экзаменов и создание других superadmin |
| `admin` | оператор заказчика | всё | всё, кроме правки экзаменов (`PUT /exams/:id` — только superadmin). Загрузка результатов, пересчёт рейтингов, удаление и восстановление, модерация, закрытие года, пользователи, сертификаты |
| `moderator` | помощник оператора | всё | создавать и править регионы, районы, школы, учителей, учеников, экзамены; править отдельные результаты. **Не может** загружать результаты из Excel, пересчитывать рейтинги, удалять, модерировать заявки, заходить в `/admin/*` |
| `regionRepresenter` | представитель RTİ | районы своего региона и всё под ними | менять фото своего региона (текстового профиля у региона нет) |
| `districtRepresenter` | представитель района | свой район | править профиль района (через модерацию) |
| `schoolDirector` | директор школы | свою школу | править профиль школы (через модерацию), фото учителей и учеников школы, файлы «Uğurlar» школы |
| `teacher` | учитель | своих учеников | править свой профиль (через модерацию), ФИО своих учеников (через модерацию), фото учеников, свои файлы «Uğurlar» |
| `student` | ученик | себя | смотреть свои результаты и рейтинги, скачивать свои сертификаты |

Для `teacher`, `schoolDirector`, `districtRepresenter` и `regionRepresenter` домашняя страница
`/panel` — профиль их сущности. Остальные видят сетку разделов. Полная матрица прав фронтенда и
описание каждой роли — в документации фронтенда (`docs/roles-and-routes.md` репозитория
`education-system-frontend`).

**Граница безопасности — бэкенд.** Фронтенд только прячет кнопки. Какие строки отдать, решает
бэкенд (см. [03-architecture.md](03-architecture.md#role-скоупинг--граница-безопасности)).

## Экзамены, типы и шкалы

- **Экзамен** (`exams`) — одно событие с названием и датой. Уникальность — `(name, date)`.
  Экзамены ежемесячные: месяц и год результата берутся из даты экзамена по календарному дню в
  `Asia/Baku`.
- **Учебный год** — сентябрь–июнь. Год обозначается годом начала: `2025` = 2025/2026
  (`src/utils/academic-year.util.ts`). `student_results.academic_year` — generated-колонка от
  `(month, year)`, поэтому результаты июля и августа не попадают ни в какой учебный год.
- **Тип экзамена** (`exam_types`) делится на **секции** по диапазонам классов
  (`exam_type_sections`, например «1-4 sinif» и «5-11 sinif»). У каждой секции — свой набор
  предметов (`exam_type_section_subjects`). Все исторические экзамены относятся к **базовому типу**
  `isim_merkezlesdirilmis` («Mərkəzləşmiş İmtahan», `is_base = true`). На нём держатся все экраны
  рейтингов. Базовый тип должен существовать всегда. Рейтинги разных типов не смешиваются:
  у всех рейтинговых таблиц и вьюх есть `exam_type_id`.
- **Число вопросов** — свойство конкретной работы, а не типа. Оно приходит в файле отдельной
  колонкой «`<предмет> (sual sayı)`». Процент результата — сумма баллов, делённая на сумму
  `question_count` по предметам этого результата.
- **Pillə (уровень)** — бэнд по проценту результата из шкалы типа экзамена (`level_scales`,
  `level_scale_bands`). Базовая шкала `isim_percent`:

  | Pillə | % | rank | Балл участия |
  |---|---|---|---|
  | E | 0–30 | 1 | 1 |
  | D | 30–50 | 2 | 2 |
  | C | 50–70 | 3 | 3 |
  | B | 70–84 | 4 | 4 |
  | A | 84–95 | 5 | 5 |
  | Lisey | 95–100 | 6 | 6 |

  Шкала читается в память при старте сервера (`src/services/levels.cache.ts`). Если поменять бэнды
  прямым SQL, нужен перезапуск.

  > Результаты, загруженные до перехода на процентную шкалу (2024/2025, 2025/2026), получили
  > pillə из файла заказчика по числу правильных ответов. У части из них сохранённый `level` не
  > совпадает с процентной шкалой. Это ожидаемо, такие результаты не пересчитываются
  > (см. [08-traps.md](08-traps.md)).

## Из чего складывается балл («xal»)

У каждого результата (`student_results`) четыре слагаемых:

| Слагаемое | Колонка | Значение | Кто ставит |
|---|---|---|---|
| Балл участия | `participation_score` | 1–6 по pillə | импорт |
| İnkişaf edən şagird | `development_score` | 10, если ранг pillə выше максимума всех более ранних результатов ученика того же типа в этом учебном году. Первый результат года развитием не считается | пересчёт |
| Ayın şagirdi (район) | `student_of_the_month_score` | 5 лучшему по `total_score` в своём классе, районе и типе за месяц | пересчёт |
| Respublika üzrə ayın şagirdi | `republic_wide_student_of_the_month_score` | 5 лучшему по `total_score` в своём классе и типе по республике | пересчёт |

Награды месяца даются, только если ранг pillə победителя не ниже `exam_types.month_award_min_rank`.
У базового типа это 6 (Lisey). NULL снимает условие. Логика — в
`src/services/stats.service.pg.ts` (`awardStudentOfTheMonth`, `markDevelopingStudents`).

Годовой балл ученика — сумма четырёх слагаемых по всем его результатам учебного года (в разрезе
типа экзамена). Средний балл («orta xal») — годовой балл, делённый на число результатов. Как
из этого получаются баллы и места учителей, школ, районов и регионов — в
[04-ratings.md](04-ratings.md).

## Словарь интерфейса

Интерфейс целиком на азербайджанском. Термины, которые встречаются в коде, комментариях и
разговорах с заказчиком:

| Термин | Значение |
|---|---|
| aylıq imtahan | ежемесячный экзамен |
| pillə | уровень ученика по результату (E…Lisey) |
| meyar | критерий (раньше в UI было «şkala») |
| xal / orta xal | балл / средний балл (слово «bal» на сайте не используется по просьбе заказчика) |
| Reytinqlər | страница рейтингов `/stats` |
| İlin şagirdləri / müəllimləri / məktəbləri / rayonları | годовые рейтинги по уровням (вкладки) |
| İnkişaf edən şagird(lər) | «развивающийся ученик», +10 за подъём pillə |
| Ayın şagirdi / Respublika üzrə ayın şagirdi | ученик месяца по району / по республике, +5 |
| Filtr üzrə yer | место внутри отфильтрованной выборки, считается на лету |
| Reytinqləri yenilə | кнопка полного пересчёта рейтингов текущего учебного года |
| Yeni tədris ili | тумблер «показывать рейтинги нового учебного года» |
| Təhsil sektoru | район (district) в терминах заказчика |
| Regional Təhsil İdarəsi (RTİ) | региональное управление (region), их 12 |
| Layihə müəllimləri | учителя, участвующие в проекте |
| Uğurlar / Nailiyyətlər | достижения в профиле учителя и школы, с файлами |
| Təsdiq gözləyən məlumatlar | очередь модерации изменений профилей |
| Silinənlər | корзина: удалённые районы, школы, учителя, ученики |
| Kitabçalar | буклеты экзаменов; раздел скрыт у всех ролей по просьбе заказчика |
| Metodika | публичная страница с описанием методики подсчёта |
| qız / oğlan | девочка / мальчик (пол ученика) |
| Köhnə kod | «старый код»: результат пришёл под прежним кодом ученика |
